边的设计 · 只用可解释信号

两种边，回答「结构」这件事

tag 边来自页面的标签，co 边来自「总是一起被召回」。语义相似是检索的事，不混进图里——这张图只讲结构。

tag 边 同标签页面两两相连：知识为什么成群
co 边 一次召回的 ids 顺手两两 +1，旧账本无 co 字段照常工作
co 记账 · recordHit
// 一次召回返回 [a, b, c]
recordHit(ids) → hits: a+1, b+1, c+1
// 共现集合顺手两两 +1
co: a-b +1, a-c +1, b-c +1

✓ 被一起需要的知识，在图上自然靠近

交互 · 四个动作

看图只是起点，动手才是终点

01 · 点选聚焦
点一个节点，淡出无关节点与边，局部结构一眼看清
02 · 侧抽屉读正文
/api/page 就地取正文，不用离开图谱页签
03 · 就地固化
暂存页（staged/）直接在抽屉里 /api/commit，两段式沉淀不用切工具
04 · focusId 跳转
从图谱一键跳到知识页签，看完正文回来继续逛图

接口 · 搜索消费 & 补充回流

11 个工具 + 12 条 API，喂给 DSH 两条通道

Agent 侧工具 · 模型直接调用（verify-plugin 钉死清单）

🔍 消费
wiki_recall 显式检索（CRAG 三分桶 + 记账）；自动预注入是隐式通道；review / sessions / lint / struggle 只读四件套
🔁 回流
wiki_learn / wiki_harvest 沉淀落 staged；wiki_acquire 缺口联网补料；wiki_commit staged→pages 唯一闸门；wiki_merge 合并提案
⚙️ 自动触发
挣扎检测（连续失败 / 撞同一堵墙 / edit-churn）+ turn/end 自动跑 wiki_acquire——回流不靠模型自觉

Client 侧 HTTP API · /aico-llm-wiki/api/*（DSH Web UI 调用）

index.js 注册 · state|page|graph|tree|commit|…
消费 GET state（8s 轮询）· page · tree · graph（独立端点不进轮询）
回流 POST commit（图谱抽屉就地固化）· harvest · capabilities · triage
辅助 GET models · POST llm · GET pending
闭环
recall 消费 → recordHit 记账（hits + co 边）

wiki_commit（人工审）→ pages/ → 回到消费侧
